# whatNotBot

Follows every account on a given Whatnot user's **Followers** list (or their Following list),
from your own logged-in Whatnot account.

Standalone — shares nothing with `gsw-bot/` or the Vite site.

## Setup

```bash
npm install
npx playwright install chromium   # only needed if real Chrome isn't used
npm run login                     # opens Chrome; log in by hand, then press Enter
```

The session is stored in `profile/` (gitignored) and reused by every later run. No
credentials are stored in code or env.

## Usage

```bash
# see what it would do, without clicking anything
node follow.js nextgenerationsportscards --dry-run --target 5

# follow 3 for real
node follow.js nextgenerationsportscards --target 3

# a real run
node follow.js nextgenerationsportscards --target 500
```

| flag | default | meaning |
|---|---|---|
| `<username>` | `nextgenerationsportscards` | whose list to work through |
| `--list` | `followers` | `followers` or `following` |
| `--target N` | `200` | stop after N *new* follows |
| `--delay MS` | `500` | base delay between follows (plus 0–MS jitter) |
| `--dry-run` | off | log intended follows, click nothing |
| `--no-filter` | off | disable the junk-username filter (see below) |

## Junk-username filter

Whatnot sorts follower lists **ascending by username**, so the head of the list is almost
entirely auto-generated throwaway accounts — `___________0`,
`00000000000000000000000000_tex`. Following those defeats the point of targeting a real
seller's audience, so `looksAutoGenerated()` in `lib/selectors.js` skips names that are
mostly digits/underscores, start with a long digit/underscore run, or contain a long
repeated-character run.

It is deliberately tuned to keep short real handles (`kj23`, `mj_23`, `2024cards`,
`00consignments`). Skipped names are recorded as `skipped` in the state file, not retried.
Pass `--no-filter` to follow the list verbatim.

## How it works

Whatnot is a Cloudflare-protected SPA: plain HTTP requests get a **403**, and headless
browsers get a challenge page. So the bot drives a **real, headed Chrome**.

There is no `/user/<name>/followers` route (it 404s) — the list is a **modal** opened by the
`N Followers` button on the profile. That modal is virtualized and infinite-scrolls, and these
lists are huge (the reference account has 25K followers and follows 305K accounts), so the bot
**streams**: it follows the rows currently loaded, scrolls, and repeats — rather than trying to
harvest the whole roster first.

Each click is verified (the button must actually flip to `Following`). A streak of unverified
clicks means server-side rate limiting, so the bot backs off 5 → 10 → 20 minutes before giving up.
Every result is written to `state/<user>-<list>.json` immediately, so an interrupted run resumes
where it stopped and never re-processes anyone.

## Stalls vs. the end of the list

There is no way to seek into the modal, so each rerun re-scrolls from the top through every
already-processed row to reach fresh names. Whatnot throttles that list fetch, so on a deep
resume the list often just **stops serving rows** — which looks identical to reaching the end.

The bot no longer assumes the happy case. When rows stop arriving it compares what it has
rendered against the count parsed off the `N Followers` button, and:

- rendered ≈ the full count → `End of list (N of ~M rows seen)`, genuinely done.
- otherwise → up to three recovery attempts (10s → 30s → 60s, each followed by a "jiggle"
  scroll up and back down to re-trigger the virtualized loader), then it exits with
  `Stalled: ... this is NOT the end of the list; rerun to continue`.

So the final line tells you which happened. A stall is not a failure — just rerun.

## When it breaks

Whatnot uses hashed CSS class names, so **all** DOM assumptions are isolated in
`lib/selectors.js`. If a run aborts with "selectors need updating", that's the only file to fix.
The bot deliberately fails loudly rather than silently clicking nothing.

## Caveats

Automating follows is very likely against Whatnot's Terms of Service. The realistic downside is
rate-limiting or action against your account. Use `--target` to keep runs modest.
